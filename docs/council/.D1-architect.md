# Architect — D1 open decisions
Lens: does the consolidated app stay coherent with PRD 01 tiering, the two-layer boundary, and the 01a data model?

- [BLOCKER] Established/Pro criteria were treated as unknown, but PRD 01 §6.3 defines them (Established: LLC/EIN verified, business bank, ≥10k monthly listeners, 12mo history, $1M cap; Pro: +2y tax records, ≥50k listeners, BD pre-screen, $5M cap), corroborated by products/creator-tier3.html and creator-tier4.html. The app ships invented targets (creator dashboard `establishedCriteria` target 100,000 listeners) that contradict the system of record. Ref: src/components/creator/data.ts:251-254, src/pages/public/ForArtists.tsx:9,32-44, PRD 01 §6.3.
- [CONCERN] Tier gates are now defined in three places (artist/tiers.ts, ForArtists.tsx, creator/data.ts). Single source: move all four tiers' gates+caps into one module and import everywhere. Ref: src/components/artist/tiers.ts.
- [CONCERN] Milestone release split diverges between the campaign wizard (default 50/50, matches Mechanism 05 §2.4 and 01a `Milestone.release_tranche_minor`) and the creator CampaignLive demo (40/35/25). Data model supports N tranches, so this is a demo-data inconsistency, not a schema one — align the demo to the wizard default. Ref: src/components/creator/data.ts:115-117.
- [CONCERN] Governance: only structural basis is Mechanism 03 (i) SPV pass-through voting. That vehicle is itself gated, and 3a-9 vehicles are per-artist — a cross-Pool "governance hub" has no backing entity. If kept, holder votes must be scoped per SPV-structured Pool (as built), never platform-wide.
- [NIT] Placeholder constants (campaign length, shipping, tip cap, replay window, SLA) are scattered across page files. Collect into `src/config/policy.ts` so product can change them in one place.
