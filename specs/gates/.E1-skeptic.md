## Strongest reason not to proceed
The money path is proven only along its happy path, using a sandbox that confirms everything instantly and never delivers events late, out of order or not at all. Every edge a real processor produces lands either in an unhandled exception that becomes a webhook 500 loop or in an outbox retry that can repeat a payout after Stripe's idempotency window has expired: delayed captures after the deadline, oversold perks, concurrent retries, chargebacks, partial and support refunds, lost refund confirmations, and milestone verifications after funding. Several of these break promises the README states as invariants ("Retries can't double-charge", "refunded automatically", milestone releases). The custody partner the design depends on is still undecided and may not support the model. Layering "enterprise" features on top now builds polish over a ledger that can drift silently from real money, for demand nobody has measured. Until a dispute/refund/late-capture state model exists, the processor is reconciled against the ledger, and at least one real backing has run end to end through the web app, more feature work only enlarges what has to be reworked later.
